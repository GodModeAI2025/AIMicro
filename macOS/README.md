# AIMicro Host

Native macOS window/menu companion for the local HTTPS bridge. Build from repository root with `macOS/build-host.sh`; the output is `macOS/AIMicro Host.app`, ad hoc signed for local use. The script copies all Server modules into Resources. Python 3 must be available at `/usr/bin/python3`.

The app starts its bundled server and passes `MICRO_REMOTE_CONFIG`, `MICRO_REMOTE_STATE_DIR` and `MICRO_REMOTE_AX_HELPER`. Pairing configuration is stored in `~/Library/Application Support/AIMicroHost/pairing.json`, outside Git. QR codes contain short lived credentials; never publish them. Stop terminates the owned server process. Revoke writes owner-only `revoke.json` for server pickup.

## Accessibility boundary

The helper uses public macOS Accessibility APIs. It never grants itself permission. The settings button opens Privacy & Security → Accessibility; macOS requires the owner to approve the app/helper. A trusted native UI and a trusted helper can have different TCC identities. The UI reports both states.

`Helper/MicroRemoteAX` reads newline-delimited JSON and produces one JSON response per line. `snapshot` enumerates candidate Codex and terminal windows with bounded trees. Generic terminal windows are not exported as Claude sessions. Only foreground native-Claude TTY proof produces `providerProven=true`; unproven candidates are excluded. No transcript content is logged. Existing-chat records are extracted only from unique AXRow/AXCell labels exposing AXSelected. Each record binds its window and exact title into a session ID; selected state and control capabilities come from the current tree. When row evidence is absent the helper exposes only inspect/focus window candidates. Chat selection, send and stop require a unique window and a proven selected chat title. Existing drafts are not overwritten. Approval/rejection require a minimal request card with explicit approval text and unique Allow once/Reject controls, bound to a request ID and selected chat. Generic buttons are insufficient. Dynamic enabled AX menu commands are advertised with IDs derived from session and menu path; approval/permission/send labels are excluded and the selected front window is verified before menu execution. Terminal/iTerm inventory reads tab TTYs via AppleEvents. The adapter binds only a known native Claude executable in the TTY foreground process group; generic shell tabs are excluded. Proven operations are inspect, focus/select and Escape stop. Existing-terminal send/approve/decline are deliberately disabled: terminal output cannot authenticate the active input or approval state and can contain misleading retained/model-produced text. The helper returns `terminalActiveInputStateNotAuthenticated`. Node/npm installations, Ghostty and other terminal applications remain unsupported by this provenance implementation. Automation permission is separate from Accessibility permission.

Dynamic menu commands are restricted to an explicit navigation/display/settings allowlist, require actual enabled AX labels and a proven Codex-specific composer context, and verify the selected front window. Any multiple distinct valid approval cards block approval; generic or localized approval menu items are excluded. The bundle name alone cannot prove a unified app is currently in Codex mode.

The QR is displayed only for the owned running server with a matching process ID, configuration written after launch, and an unexpired pairing credential. The server must include `processId` in its private pairing configuration. Stopping or expiry clears the QR.

Actions require `sessionId`, exact `title`, and for Codex mutations `chatTitle`; mismatches fail closed. The iPhone/backend must preserve those exact values from a fresh snapshot. Never fabricate selected status or actionable capabilities from a window title.

## Verification

`python3 macOS/Helper/test-binding.py` runs pure regression tests for unsafe menu-label rejection, multiple approval-scope rejection, process replacement, draft protection, approval-scope changes, generic approval rejection and malformed JSON. `App/PairingState.swift` with `Tests/main.swift` additionally verifies stopped-host, stale-configuration, PID-mismatch and expired-QR boundaries. It never queries live AX/AppleEvents sessions. Desktop computer-use inspection was blocked by the tool for com.openai.codex; no helper was used to work around that restriction. The initial permission-only helper readback returned `trusted=false` and `accessibilityPermissionRequired`; therefore real Codex AX labels and mutations remain unverified until the owner grants macOS permission. Compilation and ad hoc signing verify the native build, not real-device communication or third-party app UI compatibility.
